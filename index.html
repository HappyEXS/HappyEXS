O mnie

Początkujący ML Engineer po studiach informatycznych, skupiony na wdrażaniu modeli uczenia maszynowego jako działających aplikacji — od przygotowania danych, przez trening, po deployment i monitoring. Samodzielnie zaprojektowałem i uruchomiłem kilka projektów end-to-end: wycenę samochodów (XGBoost + FastAPI), predyktor wyników F1 (symulacja Monte Carlo, dane FastF1) oraz wielousługowy system analizy ruchu drogowego z detekcją obiektów (YOLO, PostgreSQL, Docker). Pracuję w Pythonie z ekosystemem ML (scikit-learn, XGBoost, PyTorch) i buduję pełne API oraz konteneryzowane wdrożenia. Szukam pierwszej roli, w której zdobędę doświadczenie w budowaniu modeli produkcyjnych w zespole.

Wycena samochodu używanego

Aplikacja webowa szacująca wartość rynkową używanego auta na podstawie parametrów takich jak marka, rocznik, przebieg i pojemność silnika. Sercem jest model gradient boosting (XGBoost) wytrenowany na danych ogłoszeń, udostępniony przez API FastAPI z prostym formularzem. Model ładowany jednorazowo przy starcie zwraca wycenę w milisekundach.

Predyktor wyników F1

Symulator przewidujący wyniki wyścigów Formuły 1 metodą Monte Carlo, wielokrotnie rozgrywający wyścig na podstawie oficjalnych danych pomiaru czasu (biblioteka FastF1). Backend w FastAPI z cache'owaniem danych w SQLite liczy rozkłady prawdopodobieństwa pozycji końcowych, a frontend w React (Vite + TypeScript) prezentuje je w interfejsie.

W budowie

Traffic Insights

System analizy natężenia ruchu drogowego w czasie rzeczywistym, przetwarzający obraz z publicznych kamer drogowych za pomocą detekcji obiektów (YOLO) i zliczający pojazdy według typu. Architektura wielousługowa — collector pobierający klatki, worker wykonujący inferencję, baza PostgreSQL, API FastAPI i dashboard Streamlit — zbiera dane ciągle i wizualizuje wzorce ruchu w czasie.

  • YOLO
  • PostgreSQL
  • FastAPI
  • Streamlit

W budowie

Router tras

Aplikacja wyznaczająca optymalne trasy drogowe w obrębie województwa mazowieckiego na kompletnej sieci dróg regionu. Wyznaczanie tras realizują procedury pgRouting bezpośrednio w bazie PostGIS, co utrzymuje niski narzut pamięci, a interaktywna mapa po stronie frontendu wizualizuje wynik. Projekt pokazuje pracę z danymi przestrzennymi, algorytmami grafowymi i przestrzenną bazą danych.

  • PostgreSQL
  • PostGIS
  • pgRouting
  • Python
